# 现场守护 ProcessGuard

**现场守护（ProcessGuard）**是一款 Windows 桌面守护工具，用于持续检测进程、网络端口和串口状态，并在条件满足时自动运行指定文件。它适合工位软件、扫码枪、串口设备、辅助脚本和本地服务等场景。

程序为 Windows 单文件应用。发布后的 `ProcessGuard.exe` 可直接运行，目标电脑不需要额外安装 Python 或 Java。

> **重要说明**：程序只会按照已启用的配置执行动作。建议首次使用时先关闭总开关，确认配置内容无误后再启用。

## 快速开始

### 直接运行发布文件

从构建产物中取得 `ProcessGuard.exe`，双击运行即可。程序首次启动时会显示主窗口，默认启用应用总开关，但没有任何配置，因此不会执行动作。

### 创建第一条守护配置

1. 点击主窗口右上角的“添加配置”。
2. 填写配置名称，例如“扫码软件守护”。
3. 设置检测间隔和触发后冷却时间。
4. 在“条件（IF）”区域添加一个或多个条件。
5. 在“动作（THEN）”区域添加一个运行文件。
6. 确认“配置开关”处于开启状态。
7. 确认主窗口的“应用总开关”处于开启状态。
8. 点击“保存配置”。

当条件满足时，程序会执行动作，并在主窗口中更新最近触发时间、触发次数和最近结果。

## 主窗口与开关

主窗口包含配置列表、应用总开关和配置管理按钮。

| 控件 | 作用 |
|---|---|
| **应用总开关** | 控制所有配置是否参与检测。关闭后不会检测条件，也不会执行动作。 |
| **添加配置** | 创建一套新的独立守护配置。 |
| **编辑选中** | 编辑当前选中的配置。也可以双击配置行进入编辑。 |
| **删除选中** | 删除当前选中的配置。删除前会显示确认提示。 |
| **最小化到托盘** | 隐藏主窗口，程序继续在后台检测。 |
| **切换选中配置开关** | 快速启用或停用当前选中的配置。 |

总开关和配置开关均为滑动按钮。**总开关关闭时，即使某个配置自身开启，也不会执行检测。**

## 创建和编辑配置

配置编辑窗口分为四个部分：基本设置、条件、动作和保存操作。

### 基本设置

| 项目 | 说明 |
|---|---|
| 配置名称 | 用于在主列表中识别配置，建议使用能说明用途的名称。 |
| 配置开关 | 仅控制当前配置是否启用，不影响其他配置。 |
| 检测间隔（分钟） | 两次条件检查之间的最短间隔。数值必须大于 0。 |
| 触发后冷却（分钟） | 条件触发并执行动作后，在该时间内不会再次执行同一配置。可以设置为 0。 |
| 条件逻辑 | `OR` 表示任意条件成立即触发；`AND` 表示所有条件同时成立才触发。 |

已经添加的条件或动作可以**双击进入二次编辑**。修改完成后，点击对应编辑窗口中的确定按钮即可更新内容。

### 条件操作

在“条件（IF）”区域可以添加进程、网络端口和串口条件。单击可选中条目，双击可编辑条目，使用“删除选中条件”移除条目。

### 动作操作

在“动作（THEN）”区域可以添加一个或多个运行文件动作。单击可选中条目，双击可编辑条目，使用“删除选中动作”移除条目。

## 条件说明

### 进程条件

进程条件包括“进程存在”和“进程消失”。添加进程条件时，程序会打开当前活跃进程列表，显示进程名、PID、窗口标题和内存占用。

进程选择页面支持以下操作：

- 在搜索框中按进程名或窗口标题筛选。
- 点击“刷新”重新获取当前进程列表。
- 双击进程行直接选择。
- 选中进程后点击“添加选中”。
- 选中后仍可以在后续窗口中手动修改匹配内容和匹配方式。

进程名匹配不区分大小写。旧版本没有保存匹配方式的配置会自动按精确匹配处理。

### 网络端口条件

网络端口条件包括“网络连通性”和“本机端口绑定状态”两组类型。添加条件时，填写主机地址和端口号，再从类型列表中选择所需的判断方式。

| 类型 | 成立条件 |
|---|---|
| `port_open` | 指定主机和端口可以在规定时间内建立连接。 |
| `port_idle` | 指定主机和端口无法建立连接，也就是端口掉线或不可达。 |
| `port_occupied` | 本机指定地址上的端口已经被其他程序占用，无法再次绑定。 |
| `port_free` | 本机指定地址上的端口可以被程序绑定，当前为空闲状态。 |

主机可以填写 IP 地址、主机名或 `localhost`。端口范围为 `1` 至 `65535`。如果端口填写不合法，程序不会保存该条件。

### 端口被占用和端口空闲

“可连通/掉线”检测通过连接远端服务判断网络连通性；“被占用/空闲可绑定”检测则尝试在本机绑定端口。这两组条件用途不同，不能互相替代。

| 需求 | 应使用的条件 |
|---|---|
| 判断本地服务端口是否已经被某个程序监听 | `port_occupied` |
| 判断某个本地端口是否可以用于启动服务 | `port_free` |
| 判断远程主机服务是否可以连接 | `port_open` |
| 判断远程主机服务是否掉线 | `port_idle` |

端口被占用检测适合填写 `127.0.0.1`、`localhost` 或本机网卡地址。对于远程主机，请使用 `port_open` 或 `port_idle`。

#### 端口条件示例

假设本机业务服务应该监听 `127.0.0.1:8080`，可以创建以下配置：

| 目标 | 条件 | 动作建议 |
|---|---|---|
| 服务没有启动时拉起服务 | `port_free` | 运行服务的 `.exe`、`.bat` 或其他启动文件。 |
| 端口被其他程序抢占时记录或执行处理动作 | `port_occupied` | 运行提示脚本或辅助程序。 |
| 远程 API 正常时执行后续动作 | `port_open` | 设置远程主机和端口，例如 `192.168.1.20:9000`。 |
| 远程 API 掉线时启动恢复脚本 | `port_idle` | 设置恢复脚本作为动作。 |

`port_free` 的判断方式是尝试在本机绑定 TCP 端口。绑定成功后会立即释放端口，供后续程序使用。该条件只能说明检测瞬间端口可绑定，不能保证其他程序在下一瞬间不会抢占端口。`port_occupied` 通常表示端口已经被监听，也可能表示系统权限或安全策略阻止当前程序绑定。

### 串口条件

串口条件用于检测 USB 转串口、扫码枪或工控设备等设备状态。

| 类型 | 成立条件 |
|---|---|
| `serial_present` | 指定串口存在于当前系统。 |
| `serial_missing` | 指定串口不存在于当前系统。 |
| `serial_idle` | 指定串口存在且可以被程序短暂独占打开，表示当前没有其他程序占用。 |
| `serial_busy` | 指定串口存在但无法被独占打开，通常表示正在被其他程序占用。 |

例如，业务软件仍在运行但已经失去扫码枪串口连接时，串口可能变为空闲。此时可以使用 `serial_idle` 作为触发条件。

> 串口空闲检测会尝试短暂打开串口。检测间隔不宜设置得过短，建议从 1 至 2 分钟开始测试，以降低对业务软件的影响。

## 进程匹配方式

进程条件提供三种匹配方式：精确匹配、模糊包含匹配和正则表达式匹配。三种方式都忽略英文字母大小写。

| 匹配方式 | 示例输入 | 可以匹配的进程 | 适用场景 |
|---|---|---|---|
| 精确匹配 | `ScanApp.exe` | 仅匹配 `ScanApp.exe` | 进程名称固定且明确。 |
| 模糊包含 | `chrome` | `chrome.exe`、`chrome_proxy.exe` 等包含 `chrome` 的进程 | 进程名称带版本号、后缀或多个变体。 |
| 正则表达式 | `chrome.*\\.exe` | 与表达式规则匹配的进程 | 需要多个匹配条件或更精确的模式控制。 |

选择“进程存在”时，匹配到至少一个进程即表示条件成立。选择“进程消失”时，只有一个进程都没有匹配到才表示条件成立。

### 模糊匹配使用方法

模糊匹配使用“包含”规则，不需要填写完整进程名，也不需要填写通配符 `*`。

例如，当前系统中存在以下进程：

```text
ReportClient.exe
ReportClientHelper.exe
ReportViewer.exe
```

输入 `ReportClient` 并选择“模糊包含”，可以匹配前两个进程，但不会匹配 `ReportViewer.exe`。

建议遵循以下规则：

1. 输入稳定、具有辨识度的片段，例如 `ReportClient`，不要只输入 `e` 或 `app` 这类过短内容。
2. 不要在模糊匹配中写 `.*`。如果需要使用 `.*`，应选择“正则表达式”。
3. 对于同一软件的多个辅助进程，可以使用一个足够独特的公共名称片段。
4. 如果误匹配了其他程序，应增加输入内容的长度，直到匹配范围唯一。

### 正则表达式使用方法

正则表达式可以使用 Windows 进程名进行匹配。表达式匹配对象是进程名，例如 `ReportClient.exe`，而不是完整可执行文件路径。

常用示例：

| 目标 | 正则表达式 |
|---|---|
| 匹配 `app01.exe`、`app02.exe` | `app0[12]\\.exe` |
| 匹配以 `client` 开头的 exe | `^client.*\\.exe$` |
| 匹配 `scan` 或 `scanner` | `^scan(ner)?\\.exe$` |
| 匹配带数字版本的程序 | `^tool_v[0-9]+\\.exe$` |

正则表达式输入会在保存前进行格式校验。程序还为每次正则判断设置了短时限，避免异常复杂的表达式长期占用检测线程。

> 如果只是判断名称中是否包含一段文字，优先使用“模糊包含”。只有需要起止位置、字符范围、可选片段或数字版本等规则时，才建议使用正则表达式。

## 动作说明

动作会在条件满足且不处于冷却期时执行。动作页面支持选择或手动填写以下类型的文件：

| 文件类型 | 执行方式 |
|---|---|
| `.exe` | 直接启动可执行程序。 |
| `.bat`、`.cmd` | 通过 `cmd.exe` 执行。 |
| `.ps1` | 通过 PowerShell 执行，并使用绕过脚本策略参数启动。 |
| `.com` | 按 Windows 可执行文件方式启动。 |
| `.msc`、`.svg` 和其他文件 | 使用 Windows 文件关联的默认程序打开。 |

动作配置项包括：

- **可运行文件路径**：需要填写存在的文件路径。
- **启动参数**：传递给程序、脚本或命令文件的参数。
- **工作目录**：可选。留空时使用系统默认工作目录。
- **打开前先结束残留进程**：仅对 `.exe` 和 `.com` 文件执行残留进程清理。
- **要结束的进程名**：可选。留空时默认使用运行文件的文件名；如果程序启动后进程名不同，可以手动填写。

运行 `.ps1` 时，程序相当于调用以下形式的命令：

```powershell
powershell.exe -ExecutionPolicy Bypass -File "脚本路径.ps1" 参数
```

请仅运行自己信任的脚本、批处理文件和程序。ProcessGuard 不会对外部脚本内容进行安全审查。

## 条件逻辑、检测间隔和冷却时间

### OR 和 AND

假设配置中添加了两个条件：进程存在、端口可连通。

- 使用 `OR`：两个条件只要有一个成立，配置就会触发。
- 使用 `AND`：两个条件都成立，配置才会触发。

如果目的是“进程消失或端口掉线就重启”，通常使用 `OR`。如果目的是“只有进程存在且端口正常时才执行某个动作”，可以使用 `AND`，但应特别确认动作逻辑是否符合预期。

### 检测间隔

检测间隔决定程序多久检查一次条件。间隔越短，状态变化越快被发现，但系统检查次数也越多。推荐参考以下起始值：

| 场景 | 建议检测间隔 |
|---|---:|
| 普通桌面软件 | 1 至 2 分钟 |
| 网络端口 | 0.5 至 2 分钟 |
| 串口设备 | 1 至 2 分钟 |
| 资源敏感或老旧电脑 | 2 至 5 分钟 |

### 触发后冷却

冷却时间用于防止动作重复执行。例如软件启动需要 30 秒，而条件在启动完成前仍可能保持成立，可以把冷却时间设置为 1 至 3 分钟。

## 托盘运行

关闭窗口不会退出程序。窗口关闭或点击“最小化到托盘”后，程序会隐藏到 Windows 托盘并继续检测。

- 双击托盘图标：重新显示主窗口。
- 右键托盘图标并选择“显示窗口”：重新显示主窗口。
- 右键托盘图标并选择“退出”：停止检测并退出程序。

如果需要确认程序是否仍在运行，请先检查系统托盘中的半透明雪花图标。

## 配置文件

配置默认保存到：

```text
%USERPROFILE%\\.process_guard\\configs.json
```

该文件由程序自动维护。建议优先使用界面修改配置，不要在程序运行时手动编辑文件。若需要迁移配置，可以在程序退出后复制整个 `.process_guard` 目录，并在目标用户目录下放置相同目录。

### 导出配置

在主窗口底部点击“导出配置”，选择保存目录和 JSON 文件名即可。导出的文件包含应用总开关状态以及全部配置，适合备份、迁移和提交给其他同事复核。

推荐的备份流程如下：

1. 先确认当前配置已经保存，并检查主配置列表中的配置数量。
2. 点击“导出配置”。
3. 选择一个有写入权限的目录，例如 U 盘、项目备份目录或用户文档目录。
4. 保留 `.json` 扩展名并点击保存。
5. 使用文本编辑器查看文件时，只建议阅读，不要在程序运行时直接修改。

导出的 JSON 中可能包含本机文件路径、工作目录、进程名称和端口信息。分享文件前请确认其中没有敏感路径、内部主机地址或其他不应公开的信息。

### 导入配置

在主窗口底部点击“导入配置”，选择之前导出的 JSON 文件。导入采用**追加模式**，不会删除或覆盖当前配置。程序会为每条导入配置生成新的内部 ID，因此即使导入同一个文件两次，也不会因为 ID 相同而互相覆盖。

推荐的迁移流程如下：

1. 在旧电脑上点击“导出配置”，保存 JSON 文件。
2. 将 JSON 文件复制到新电脑。
3. 在新电脑启动 ProcessGuard，并点击“导入配置”。
4. 选择 JSON 文件，等待导入成功提示。
5. 逐条编辑导入的配置，确认新电脑上的运行文件路径、工作目录、进程名、端口和串口号。
6. 先保持配置开关关闭，手动测试条件和动作后再启用。

导入不会同步文件本身，也不会把旧电脑上的 `.exe`、脚本或其他动作文件复制到新电脑。导入的只是配置文本，因此动作依赖的文件必须在目标电脑上单独部署。

导入后请检查以下内容：

1. 运行文件路径是否在当前电脑存在。
2. 进程名称和匹配方式是否适合当前电脑。
3. 端口和串口号是否与当前设备一致。
4. 配置开关和应用总开关是否符合预期。

导入文件必须是有效的 JSON 配置文件。导入失败时，当前配置不会被修改。

导入同一文件多次会产生多份独立配置。若误重复导入，可以在主配置列表中选择多余配置并删除；删除前建议根据配置名称、条件和动作逐条核对。

## 常见问题

### 进程存在，但“进程存在”条件没有成立

先点击进程搜索页面的“刷新”，确认进程名。然后检查是否误选了精确匹配。对于带辅助进程或版本后缀的程序，可以改用模糊包含匹配。使用正则表达式时，请确认表达式匹配的是进程名而不是完整路径。

### 进程消失条件一直成立

检查填写的进程名是否包含错误字符或多余空格。确认程序是否实际以另一个进程名运行。可以从当前活跃进程列表重新选择目标进程。

### 脚本没有运行

确认文件路径存在，并确认脚本本身可以独立运行。PowerShell 脚本需要使用 `.ps1` 扩展名。批处理文件建议使用 `.bat` 或 `.cmd` 扩展名。如果脚本依赖特定工作目录，请填写“工作目录”。

### 动作重复执行

增大“触发后冷却”时间，并检查条件是否使用了 `OR` 导致多个条件重复触发。对于启动较慢的软件，应让冷却时间覆盖软件启动和初始化时间。

### 串口条件状态不稳定

避免把串口检测间隔设置得过短。确认串口号没有发生变化，并注意某些驱动可能会在设备重新连接后分配新的 COM 号。

### 关闭窗口后没有检测

关闭窗口默认只是隐藏到托盘。检查托盘中是否存在半透明雪花图标，并确认应用总开关和目标配置开关均已开启。如果托盘图标不存在，程序可能已经退出。

## 本地构建

本地构建需要安装 [.NET 8 SDK][1]。项目目标框架为 `net8.0-windows`，并使用 Windows Forms。

在 Windows 命令提示符或 PowerShell 中进入项目目录后执行：

```bat
dotnet restore
dotnet publish -c Release -r win-x64 --self-contained true
```

发布产物位于：

```text
bin\\Release\\net8.0-windows\\win-x64\\publish\\ProcessGuard.exe
```

项目也提供了 `build.bat`，可以在 Windows 环境中按项目预设流程构建。

### 本地代码签名（可选）

如果拥有代码签名证书，可以使用 Windows SDK 中的 `signtool.exe`：

```bat
signtool sign /f cert.pfx /p 证书密码 /tr http://timestamp.digicert.com /td sha256 /fd sha256 ProcessGuard.exe
signtool verify /pa ProcessGuard.exe
```

## GitHub Actions 自动构建

仓库中的 `.github/workflows/build-windows.yml` 会在推送到 `main` 或 `master` 分支时自动构建 Windows 单文件程序，也支持手动触发。

推送版本标签时，工作流还会创建 GitHub Release。例如：

```bat
git tag v1.1.0
git push origin v1.1.0
```

未配置证书时，工作流会跳过签名，但仍会生成未签名的 EXE。

### 配置自动签名

在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 中添加以下 Secrets：

| Secret | 内容 |
|---|---|
| `WINDOWS_CERT_PFX` | PFX 证书文件的 Base64 内容。 |
| `WINDOWS_CERT_PASSWORD` | PFX 证书密码。 |

在 PowerShell 中生成 Base64：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Set-Clipboard
```
